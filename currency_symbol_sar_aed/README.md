# SAR and AED Currency Signs

Shows Saudi riyal and UAE dirham amounts with their official signs, placed
before the amount as both central banks prescribe:

| Currency | Odoo's default | With this addon | Unicode |
|---|---|---|---|
| Saudi riyal (SAR) | `1,234.50 SR` | `⃁ 1,234.50` | U+20C1 SAUDI RIYAL SIGN, Unicode 17.0 (2025) |
| UAE dirham (AED) | `1,234.50 AED` | `⃃ 1,234.50` | U+20C3 UAE DIRHAM SIGN, Unicode 18.0 (2026) |

Both signs are new, and few fonts draw them yet: most devices would show an
empty box. The addon therefore ships a small font (about 2 KB) that holds only
these two signs, and makes Odoo's backend, website, portal and reports use it
for them.

## What changes

* **Currency symbols.** SAR and AED get the new signs, positioned before the
  amount, in every language.
* **Backend and website.** The sign font is loaded with the backend and the
  frontend (website, portal) styles and put first in Odoo's font stacks. Its
  `unicode-range` limits it to the two signs, so every other character keeps
  its usual font.
* **Reports, HTML and PDF.** Invoices, quotations and other reports keep their
  own fonts, with the sign font as a fallback, both in the browser preview and
  in PDFs printed by wkhtmltopdf.
* **Fallback.** If the font fails to load, the device's own fonts take over.
  Some already draw the riyal sign (Windows does).

Emails, spreadsheet exports and anything else that leaves Odoo carry the plain
Unicode character. Whether the reader sees the sign then depends on their
fonts. The font is added to the backend, frontend and report styles only;
interfaces with their own style bundles depend on the device's fonts too.

## Install and uninstall

Install **SAR and AED Currency Signs** from Apps. Nothing to configure. The
install rebuilds Odoo's stored company report stylesheet so PDFs pick up the
font right away.

Uninstalling puts back Odoo's defaults (`SR` and `AED`, after the amount) for
each currency whose symbol is still the new sign; a symbol someone has changed
in the meantime is left alone.

## How the font reaches each place

Odoo draws text with font stacks and needs different handling per renderer.
The comments in `static/src/scss/` explain each case; in short:

* `font_stack.scss` overrides Odoo's `o-add-unicode-support-font` SCSS
  function so the backend and frontend stacks start with `'SAR AED Signs'`.
  It has to come first: Chrome on Windows draws U+20C3 as a missing-glyph box
  when an installed font such as Segoe UI comes before the font that has it.
* `report.scss` adds the signs to the `Odoo Unicode Support Noto` family that
  report layouts already list, at the weights and styles Odoo declares, and
  `views/report_templates.xml` appends the font to the company report font.
* wkhtmltopdf only loads a web font when some text uses it as first choice,
  so `report.scss` adds a hidden, absolutely positioned copy of the two signs
  at the top of the document. It takes no space and cannot push content onto
  an extra page.

## Rebuilding the font

`static/fonts/sar_aed_signs.ttf` is generated by `tools/build_font.py` with
[fontTools](https://github.com/fonttools/fonttools) from two openly licensed
fonts, keeping only the two code points and scaling both glyphs to cap height
on the baseline:

```bash
pip install fonttools
# saudi_riyal.ttf: npm @emran-alhaddad/saudi-riyal-font 1.1.0, fonts/regular/saudi_riyal.ttf
# dirham.ttf:      npm dirham 1.5.3, dist/fonts/dirham.ttf
python tools/build_font.py saudi_riyal.ttf dirham.ttf static/fonts/sar_aed_signs.ttf
```

## Tests

```bash
odoo -d test_db -i currency_symbol_sar_aed --test-enable \
  --test-tags /currency_symbol_sar_aed --stop-after-init
```

They check the formatted amounts, the order of the style files in the
backend, frontend and report bundles, and the company report stylesheet.
